# ADR-0114：以媒体库播放器作为服务运行边界

状态：采用。

## 决策

QMaxHub 的服务负责已有媒体的索引、资料浏览与播放。本地 NFO、封面、横幅和人物资料沿用现有解析与账本模型；目录扫描不写媒体。服务缺少本地资料时使用文件名，不派发在线资料采集。

影片与人物刮削、关注订阅、RSS、新作发现、资源检索、云下载、浏览历史口味采集和候选复核不属于运行接口。服务不注册对应路由，不创建其调度器，也不恢复这些任务或联网补图。旧深链不能触发旧任务。

保留媒体库、搜索、人物与标签浏览、播放列表、收藏与观看记录、STRM、字幕、FFmpeg 转码和基本设置。已有数据库不做破坏性迁移，不删除媒体、人物、订阅配置、候选或任务历史。

## 分发与依赖

默认 Python 依赖只包含媒体库服务实际需要的第三方库。历史模块、维护脚本及桌面工具的回归依赖归开发环境；测试环境不作为镜像运行环境。

Docker 不安装 vision extra，不准备或携带人脸模型。继续使用 Debian FFmpeg 和既有 VAAPI 软件栈。Debian FFmpeg 经 SDL/OpenGL 依赖 Mesa/LLVM，不能通过直接删除共享库获得可靠的精简结果；无界面 FFmpeg 需要独立构建和播放验收。

前端沿用 React 与现有 UI 组件，仅将媒体库所需页面接入生产路由与启动链。构建产物随源码一起交付。

## 验证

隔离数据库验证本地扫描、NFO 导入、记录保留、核心 API 和被清退 API 的不可达性。使用只安装默认依赖的独立环境验证完整服务启动。桌面页面核对导航、设置、人物和详情入口及播放。

镜像冒烟验证非 root、鉴权、扫描、Range、软件转码回退、重载和重启持久化，并核对视觉、爬虫、下载及桌面依赖不在镜像中。工作流记录镜像展开大小。源码测试不能代替 Linux 镜像构建与容器验收。
